# WispTerm v1.40.6

> Patch release that fixes two memory leaks behind the multi-gigabyte footprint
> long-running macOS sessions reached (one report: 4.7GB after a day and a
> half). AppKit objects autoreleased by the window loop are now freed every
> iteration, and fallback fonts are loaded once per font instead of once per
> character. No configuration migration is required.

## Fixed

- **macOS autorelease leak in the window loop.** WispTerm does not start
  through `NSApplicationMain`, so the main thread had no outer autorelease
  pool, and AppKit objects autoreleased outside an explicit
  `@autoreleasepool` were never freed. The largest source was
  `-[NSWindow isZoomed]`, polled every frame to draw the titlebar and remember
  the window position: each call left behind about four empty
  `NSMutableArray`s plus pool bookkeeping, roughly 290 objects per second
  under continuous output and about 3.3GB of the 4.7GB report. The window
  loop now opens an autorelease pool per iteration
  (`window_backend.beginLoopIteration`, the same pattern as Ghostty's Metal
  renderer), the zoomed state is cached from window-delegate callbacks instead
  of being queried every frame, and every exported Objective-C bridge function
  opens its own pool. A new source guard
  (`src/source_guards/objc_autorelease_guard.zig`) keeps it that way. On the
  same build with continuous terminal output the array count stayed flat
  after the fix.

- **Fallback font memory growth.** WispTerm opened a new copy of a fallback
  font for every character that the primary font lacked. On macOS 26,
  PingFang is loaded from a copy of its font data (about 768KB) because
  FreeType cannot open its file, so 800 different Chinese characters kept
  800 copies of PingFang in memory, about 1.2GB after a day and a half.
  Each fallback font is now loaded and sized once and shared by every
  character it covers, as Ghostty's font collection does. Fonts are matched
  by PostScript name (macOS) or file path and face index, so the same font
  is never opened twice. Fonts named in `font-family-cjk` or
  `font-family-fallback` still take priority over other fallback fonts. The memory report
  from `wispterm-debug-memory` shows `fallback_faces` (fonts) and the new
  `fallback_cps` (characters mapped to them).

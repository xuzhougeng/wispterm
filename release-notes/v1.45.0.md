# WispTerm v1.45.0

> Signed Windows binaries and uninterrupted in-place updates: from this
> release on, a Windows portable install downloads the next version in the
> background and restarts into it from the titlebar. Updating *to* v1.45.0
> from v1.44.0 or earlier is still manual (download the zip and run
> `Replace-WispTerm.cmd`); later releases update themselves. No configuration
> migration is required.

## Added

- **Uninterrupted in-place updates on Windows (#686).** With the new
  `auto-update = download` (the default), a signed Windows portable install
  downloads a newer release in the background, checks it against the SHA-256
  digest GitHub publishes for the asset, and requires every program and
  library in it to carry a valid Authenticode signature, WispTerm's own from
  the same publisher as the running copy. An **Update** button then appears in
  the titlebar, left of the Command Center button. Clicking it asks before
  restarting (tabs close): the running files are moved aside, the new ones put
  in place, and the new version started; if it does not come up within 20
  seconds the swap is undone and the current version keeps running. Choose
  **Later**, or just quit, and the update installs on exit so the next launch
  runs it. The key and its values (`off | check | download`) match Ghostty's
  `auto-update`; `auto-update-check = false` still turns updates off.
  Development builds, folders WispTerm cannot write to, macOS and Linux keep
  the existing download-and-replace flow.

- **Authenticode-signed Windows release binaries (#685).** `wispterm.exe`,
  `wispterm-ssh-askpass.exe` and the Explorer shell extension in every Windows
  zip are signed with SSL.com eSigner and timestamped, so Windows can identify
  the publisher and the in-place updater can verify a download. A new
  certificate still has to build SmartScreen reputation over time.

- **Click a ←/→ choice row to cycle it (#684).** The Copilot profile form's
  protocol and vision rows and the SSH form's auth-method row change on a
  mouse click as well as with the arrow keys, and launcher clicks repaint
  immediately.

## Fixed

- **Windows release signing fails loudly (#687).** SSL.com CodeSignTool can
  exit 0 even when eSigner rejects the login or the one-time code. The release
  workflow now reads its output and log to decide whether signing worked, and
  retries a rejected code in the next TOTP window, so an unsigned build can no
  longer be published by mistake.

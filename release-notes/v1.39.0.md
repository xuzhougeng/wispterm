# WispTerm v1.39.0

> Copilot follow-ups queued while a request is running can be sent into the
> conversation with Enter, or returned to the input with Esc. Wide Markdown
> tables pan instead of wrapping every long cell, and Ctrl+V paste into Vim
> keeps a complete bracketed-paste frame. No configuration migration is
> required.

## Added

- **Send queued follow-ups now (#634).** Prompts submitted while Copilot is
  busy still queue. On the Queued Prompts panel, Enter cancel-and-sends the
  selected row into the conversation as the next user turn (Codex / Claude
  Code / Grok-style guidance). Esc returns that row to the composer to edit
  without stopping the in-flight request. An empty composer Enter also
  send-nows the queue head if the panel was dismissed. The Copilot sidebar
  no longer treats Esc as Stop / hide while the panel is open.

## Improved

- **Wide Markdown tables (#635, #624).** Tables that overflow the message keep
  their natural column widths, clip to the bubble, and pan horizontally when
  you scroll the wheel over them. A thumb shows overflow position. Tables that
  still fit wrap as before. Selection and the table copy button follow the pan
  offset.

## Fixed

- **Bracketed paste framing (#633, #632).** Clipboard paste snapshots the
  negotiated mode 2004 under the PTY-reader lock and queues the start marker,
  body, and end marker as one frame, matching Ghostty's `completeClipboardPaste`
  locking. Multiline Vim pastes no longer lose the body or end marker when the
  mailbox has a single free slot. On Windows, OpenSSH 7.7 can still drop the
  markers in the console transport; check `ssh -V` and use OpenSSH 8.1+ if
  remote Vim still auto-indents. See the FAQ.

## Compatibility

- This is a desktop-only release; WispTerm Remote web console versions are
  unchanged. Linux AppImage remains experimental.
- Issue #632 remains open until a current Windows OpenSSH session is confirmed
  on the reporter's machine. Issue #624 remains open for a fuller GFM renderer.

## Performance baseline

- The Windows x86_64 CPU terminal-stream baseline is attached to the GitHub
  release as `benchmark-windows-v1.39.0.md`, collected with
  `wispterm-bench --case terminal-stream --duration 1000` in ReleaseFast mode.
  It measures parser throughput, not GPU rendering or input latency.

# WispTerm v1.39.0（中文）

> Copilot 在忙时排队的 follow-up 可用 Enter 立刻送进对话，或用 Esc 取回输入框
> 编辑。过宽的 Markdown 表格改为横向平移，不再把每个长单元格挤成一叠换行。
> Ctrl+V 粘贴进 Vim 会保持完整的 bracketed-paste 帧。无需手动迁移配置。

## 新增

- **立刻发送排队的 follow-up（#634）。** Copilot 忙时提交的 prompt 仍会入队。
  在 Queued Prompts 面板上，Enter 会打断当前回合并把选中项作为下一条用户消息
  送进对话（与 Codex / Claude Code / Grok 的引导方式相同）。Esc 把该项取回
  输入框编辑，不停止正在进行的请求。面板关掉后，空输入再按 Enter 也会立刻
  发送队首。Copilot 侧栏在面板打开时不再把 Esc 当成 Stop / 关闭。

## 改进

- **过宽的 Markdown 表格（#635，#624）。** 超出消息宽度的表格保持测量列宽，
  裁在气泡内，鼠标滚轮在表格上横向平移，底部有滑块。仍能放下的表格继续换行。
  选区和表格复制按钮跟同一套偏移。

## 修复

- **Bracketed paste 分帧（#633，#632）。** 粘贴在 PTY 读线程同一把锁下快照
  协商好的 mode 2004，并把起始标记、正文、结束标记作为一帧入队，对齐 Ghostty
  的 `completeClipboardPaste`。mailbox 只剩一格时，多行 Vim 粘贴不会丢掉正文
  或结束标记。Windows 上 OpenSSH 7.7 仍可能在控制台传输层丢掉这些标记；若
  远程 Vim 还会自动缩进，请看 `ssh -V` 并改用 OpenSSH 8.1+。详见 FAQ。

## 兼容性

- 本次仅发布桌面应用，WispTerm Remote 网页控制台版本不变。Linux AppImage
  仍为实验性构建。
- #632 在报告者机器上用当前 Windows OpenSSH 确认之前保持开放。#624 的完整
  GFM 渲染仍未完成。

## 性能基线

- GitHub Release 附带 `benchmark-windows-v1.39.0.md`，记录 Windows x86_64 上
  ReleaseFast 构建运行 `wispterm-bench --case terminal-stream --duration 1000`
  的结果。该基线衡量终端解析吞吐量，不代表 GPU 渲染或输入延迟。

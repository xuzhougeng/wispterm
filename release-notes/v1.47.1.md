# WispTerm v1.47.1

> Fixes for scrolling in full-screen terminal apps: every Windows package now
> carries the modern ConPTY so mouse reporting reaches WispTerm, synchronized
> frames paint as soon as they finish, and wheel deltas accumulate into whole
> rows. A v1.47.0 Windows install picks this release up through the in-place
> updater; the titlebar shows **Update** and a restart finishes it. No
> configuration migration is required.

## Changed

- **Every Windows package bundles the modern ConPTY (#727).** `conpty.dll` and
  `OpenConsole.exe` now ship in the installer, the portable zip and the
  portable OpenGL zip, not only in portable-compat. WispTerm already prefers
  the pair when both files sit next to `wispterm.exe`
  (`windows-conpty = auto`, the default); set `windows-conpty = system` to
  keep the OS in-box console host.

## Fixed

- **The mouse wheel sent arrow keys to a TUI that had enabled mouse reporting
  on Windows (#727).** The in-box console host forwards an application's
  mouse-mode requests (`?1000h`, `?1002h`, `?1003h`, `?1006h`) to the terminal
  only while that application has VT input enabled. An application that turns
  mouse reporting on first, such as Pi's fullscreen mode, never reached
  WispTerm's mouse state, so the wheel fell back to Up/Down keys on the
  alternate screen instead of SGR mouse reports. The bundled console host
  passes the requests through. This fix was not verified on a Windows machine
  before release; if the wheel still sends arrow keys, please reopen #727.
- **Scrolling Codex over SSH dropped to single-digit FPS and moved in jumps
  (#717).** A chunk that started or ended a synchronized-output frame (mode
  2026) posted no wakeup, so a finished frame was drawn only on the render
  loop's idle timeout, or skipped when the next frame began first. The IO
  thread now wakes the renderer when the application ends a frame.
- **Small wheel deltas flooded mouse-reporting TUIs (#717).** Every wheel
  event was rounded up to at least one report or cursor key, so touchpads,
  high-resolution wheels and remote-desktop injectors sent far more reports
  than rows scrolled, while the scrollback path dropped the same small deltas.
  Deltas now accumulate per surface into whole rows with the remainder carried
  over. A full detent is still three rows.
- **Previewing a `~\...` path failed on Windows (#725).** A path such as
  `~\AppData\Local\Temp\shot.png` was resolved as a relative directory under
  the WispTerm install folder and ended in "Image preview failed". Home paths
  are now expanded before the terminal's working directory is applied.
- **Long release notes overflowed the What's New dialog (#723).** A long
  summary could grow the header past the dialog, paint over the footer
  buttons and push the rest of the notes out of the panel. The title and
  buttons now stay fixed while the notes scroll inside a clipped region, and
  the buttons stack in narrow windows.

## Internal

- `assistant/conversation/session.zig` was split into results, export and
  composer modules (9,990 to 7,970 lines) with no behavior change (#724).
- Source-guard ratchets lowered: `input.zig` direct dirty writes 22 to 4,
  conversation-session globals 13 to 8, overlay globals 22 to 21.

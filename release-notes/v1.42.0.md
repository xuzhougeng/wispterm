# WispTerm v1.42.0

> Sync your Password Store, Agent history, SSH hosts and AI profiles across
> computers through WebDAV or a synced folder, with end-to-end encryption.
> No configuration migration is required; sync is opt-in.

## Added

- **Encrypted sync (#674).** Open Command Center → **Sync** to connect your
  computers to a drive you already use.
  - **WebDAV or a synced folder.** Connect to a WebDAV service such as 坚果云
    (Jianguoyun), Nextcloud, ownCloud, Synology or InfiniCloud, or choose a
    folder synced by OneDrive, iCloud Drive, Dropbox or another drive client.
  - **Choose what to sync.** Enable the Password Store, WispTerm Agent / Copilot
    conversation history, SSH hosts and AI profiles independently. Run
    **Sync Now** from the page or Command Center, or enable automatic sync
    every 5, 15, 30 or 60 minutes. With automatic sync enabled, WispTerm also
    syncs shortly after launch and about a minute after a password, SSH host
    or AI profile changes.
  - **Encrypted before upload.** A sync passphrase derives the key with
    Argon2id; XChaCha20-Poly1305 encrypts the synced data before it leaves
    your computer. The passphrase is never stored, and the derived key and
    WebDAV password are protected locally by the Password Store's key
    (macOS Keychain / Windows DPAPI). Passwords received from another
    computer are re-encrypted with this computer's own key.
  - **Merge individual items.** Changes and deletions travel between
    computers. Concurrent edits to the same item use the newer modification
    time; a missing local data file is restored from the drive. Saving a
    locally open password or profile editor preserves new entries received
    in the meantime.
  - **Set up another computer** with the same drive folder and sync
    passphrase (at least 8 characters). **Forget on this computer** removes
    its sync settings without deleting local data or anything on the drive.
    Keep the passphrase safe: encrypted drive data cannot be recovered
    without it. See the [Sync guide](https://github.com/xuzhougeng/wispterm/blob/v1.42.0/docs/sync.md)
    for setup and troubleshooting.

## Improved

- **Password input without exposing the secret to the agent (#673).**
  `password_input` replaces `password_get`: after you approve, WispTerm types
  the stored password directly into the terminal password prompt and presses
  Enter. The agent sees the entry name and masked output. Every use requires
  approval, including at the `full` permission level, and the password prompt
  is checked again before typing. An existing opt-out for `password_get`
  also disables `password_input`. Previously saved conversation history is
  not rewritten.

## Fixed

- **macOS dictation and voice input methods (#672).** Dictation and voice
  input methods can insert text into terminal tabs and the AI composer.
  Interim composition text now repaints even when no keyboard event arrives,
  and input-method selection ranges correctly handle Chinese and other
  multi-byte text.

## Sync limitations

- Conflict resolution uses each computer's clock; keep the clocks in sync.
- An already open Agent conversation keeps its in-memory copy. Reopen it to
  see synced history; sending another message first saves the open copy.
- On experimental Linux builds, create WebDAV folders on the drive manually
  before syncing; automatic folder creation is unavailable. Synced-folder
  sync is unaffected.

## Performance baseline

CPU-only reference measured on the Linux x86_64 release-preparation host
(16 logical cores), using Zig 0.15.2 and `ReleaseFast`:

```sh
wispterm-bench --case terminal-stream --duration 1000
```

| Version | Scenario | Throughput (MiB/s) | Iterations | Duration (ms) |
|---|---|---|---|---|
| 1.42.0 | terminal-stream | 60.64 | 971 | 1000 |

This measures VT parsing on this host; it does not measure GUI rendering or
input latency on Windows or macOS.

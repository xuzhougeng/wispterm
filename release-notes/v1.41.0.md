# WispTerm v1.41.0

> Adds an encrypted Password Store that you and the AI agent share, and
> Ghostty's `env` config key for the environment of local shells. No
> configuration migration is required.

## Added

- **Password Store (#668, #670).** Command Center → **Password Store** opens a
  Settings-style page. The left rail lists your entries, and the right side
  shows the selected entry's name, username, password, note, and whether the
  agent may read it, plus Copy password and Delete entry. Keyboard, mouse,
  the wheel, and paste all work. You can also type an entry name (or `pass`)
  in the Command Center and press Enter on its `Password: <name>` row to copy
  the password.
  - **Encrypted on disk.** Each password is sealed with XChaCha20-Poly1305 in
    `passwords` in the config directory. The key is kept by the OS, not next
    to the file: the login Keychain on macOS and a DPAPI-sealed
    `passwords.key` on Windows. Linux, which is still experimental, falls
    back to an owner-only `passwords.key` (see `KNOWN_ISSUES.md`). Opening the
    file, or a shell command that `cat`s it, shows names and notes but no
    password.
  - **Hidden by default.** Passwords show as `••••••••`. Turn on **Show
    password** to read one; it is hidden again and wiped from memory when you
    switch entries, leave the tab, or close it. Editing a password types or
    pastes a replacement and never shows the old one.
  - **For the agent.** The new `password_get` tool reads one entry by name
    for sudo, a database login, or an SSH password. Every read shows an
    approval prompt naming the entry, at every permission level including
    `full`, and the password is decrypted only after you approve. Turn off
    **Allow agent** on an entry to refuse it without a prompt. An unknown name
    returns the available names with their username and note, never a
    password. Disable the tool in Skill Center if the agent should never see
    secrets.
  - On macOS, the first Keychain access after installing or updating may ask
    you to allow WispTerm once.

- **`env` config key (#667, #669).** `env = KEY=VALUE` sets an environment
  variable for every local shell and command WispTerm starts, with Ghostty's
  rules: the key is repeatable, `env =` clears the list, `env = KEY=` drops
  `KEY`, and a later `KEY` wins. Your values are applied after WispTerm's own
  `TERM` / `TERM_PROGRAM`, so they override them. For example,
  `shell = D:\msys64\usr\bin\fish.exe --login` with `env = MSYSTEM=CLANG64`
  starts an MSYS2 CLANG64 shell. The variables apply to the local process,
  including a local `ssh` client, not to the remote shell.

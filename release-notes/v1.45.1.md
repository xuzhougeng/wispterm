# WispTerm v1.45.1

> A Windows installer joins the portable zips, and the release pipeline
> signs every binary the way SSL.com's malware scan expects. This is also the
> first release a v1.45.0 install picks up through the new in-place updater:
> the titlebar shows **Update**, and a restart (or the next launch after
> quitting) finishes it. No configuration migration is required.

## Added

- **Windows installer (#689).** `wispterm-windows-setup-v1.45.1.exe` installs
  WispTerm for the current user, with no administrator prompt, into
  `%LOCALAPPDATA%\Programs\WispTerm`, adds a Start menu shortcut and an
  Add/Remove Programs entry, and offers the Explorer context menu and a
  desktop shortcut as optional components. It is signed, and it wraps the
  already-signed portable build, so the installed files are byte-for-byte the
  portable ones: in-place updates, `Replace-WispTerm.cmd` and
  `Add-Context-Menu.cmd` all keep working on an installed copy, and
  uninstalling keeps your configuration and plugins. `/S` installs silently,
  `/D=<folder>` picks the folder, `/MENU` and `/DESKTOP` select the optional
  components. The portable zips are unchanged for anyone who prefers them.

## Fixed

- **Windows release signing works with eSigner's malware scan (#688).** The
  v1.45.0 tag first failed to sign because the pipeline submitted file hashes
  (`batch_sign`), which SSL.com rejects when the credential's Malware Blocker
  is on. Each binary is now uploaded and signed with `sign`, so the scan runs
  before signing; identical files shared between packages are signed once.

# WispTerm v1.46.0

> SSH profiles can now reach their server through a SOCKS5 or HTTP CONNECT
> proxy, a Magpie-managed model shows up as a read-only AI profile, and an
> in-flight AI request no longer repaints the window at display refresh rate.
> A v1.45.x Windows install picks this release up through the in-place
> updater; the titlebar shows **Update** and a restart finishes it. No
> configuration migration is required.

## Added

- **Per-profile SOCKS5 and HTTP CONNECT proxies for SSH (#693, closes #692).**
  The SSH profile form gains a network route: *No proxy*, *SOCKS5* or
  *HTTP CONNECT*, with a proxy host and port. The route is per profile, not a
  system proxy and not the AI/research HTTP proxy. WispTerm bundles a small
  `wispterm-ssh-proxy` stdio bridge and passes it to OpenSSH as
  `ProxyCommand`, so OpenSSH still owns authentication and host-key checks and
  no external `nc`/`corkscrew` is needed. The same route carries through
  interactive sessions, reconnect / split / session restore, SCP and the
  remote file explorer, SSH and HTML tunnels, and port forwarding. Proxies that
  require authentication are reported explicitly rather than reusing SSH
  credentials, and a profile that sets both a proxy and `ProxyJump` is
  rejected instead of silently dropping one route. Contributed by
  [@jarxunlai](https://github.com/jarxunlai).
- **Magpie model connection (#696).** When the Magpie Agent plugin writes
  `~/.config/wispterm/magpie.json`, WispTerm reads it into a read-only
  **Magpie** AI profile (OpenAI Chat Completions, model id passed through) and
  uses it as the default for new Agent / Copilot sessions. Personal profiles
  stay selectable and are never rewritten: the managed profile is not saved to
  `ai_profiles`, cannot be edited or deleted in the form, gets its own slot so
  all 16 personal profiles remain available, and does not touch the saved
  `ai-default-profile`. Missing, partial, malformed or non-http(s) files read
  as inactive. See `docs/magpie.md` in the repository.

## Changed

- **AI requests no longer spin the render loop (#696).** While a request was
  in flight — including minutes parked on a tool-approval dialog — the window
  repainted at 60–120 fps with nothing changing. Sessions now flag the UI only
  when streamed content, status, tool cards or prompts actually change, with a
  slow 500 ms heartbeat as a safety net, so an idle request costs almost no
  CPU.
- **The config file is stat'ed at most once a second (#696)** instead of on
  every loop wake. Creating, renaming or deleting the file is still picked up
  at once through the directory watcher; an in-place edit shows up within a
  second plus the existing reload debounce.

## Fixed

- **Windows: the IME preedit repaints as soon as it changes (#694, #691).**
  Pinyin and other compositions arrive as `VK_PROCESSKEY`, which painted
  nothing, so the inline preedit only showed on the next cursor blink or mouse
  move. Each change to the composition text now requests a frame.
- **macOS: ⌘Q and ⌘H reach the app menu from a focused window (#695).** The
  terminal view claimed every ⌘ key for the keybind path, so the system Quit
  and Hide items only worked while a menu was open.
- **Paste Image tells you what happened (#695).** Ctrl/Cmd+Shift+V in the
  Copilot composer shows a toast when the clipboard holds no image (and
  whether text was pasted instead), when the image cannot be read, and for the
  existing too-large / vision-off cases.
- **macOS: a dispatch semaphore leaked on every HTTP request and WebSocket
  call (#696).** The bridges build without ARC, so the release was compiled
  out; it is now gated on `OS_OBJECT_USE_OBJC_RETAIN_RELEASE`.
- **Kitty graphics textures are freed when the image leaves the terminal
  (#696).** Deleted or evicted images used to keep their GPU texture resident
  until the surface closed, so long image-heavy sessions pinned VRAM for every
  image they had ever shown.

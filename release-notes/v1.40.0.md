# WispTerm v1.40.0

> Codex, Kimi, and xAI subscriptions can sign in from the LLM provider form.
> Model requests can use the system proxy or a specific `host:port`. `/btw`
> side conversations can call tools. No configuration migration is required.

## Added

- **Codex, Kimi, and xAI subscription sign-in (#641).** The New/Edit LLM
  Provider form starts a device-code login and opens the browser after the
  code is issued. Codex requires sign-in. Kimi and xAI still accept an API key.
  Tokens are stored in `oauth.json` next to `ai_profiles` and refresh
  automatically. The ACP external-agent path is removed; a saved `acp` profile
  loads as a normal HTTP profile.

- **Choose the proxy for model HTTP (#643).** Settings → AI & Integrations has
  **Use proxy** and **Proxy**. Off keeps a direct connection. On with an empty
  address uses the system proxy: WinHTTP on Windows, the system session on
  macOS, and `https_proxy` / `http_proxy` / `all_proxy` on Linux. Set
  `http-proxy` to `127.0.0.1:6789` or `http://host:port` to pin one local
  proxy when several are running. While the switch is on, a streamed reply is
  shown after the full response arrives.

- **Tool calls in `/btw` (#638).** A side conversation opened with `/btw` can
  use the same assistant tools as the main Copilot turn.

## Fixed

- **Subscription login opens the browser (#642).** The verification page opens
  only after the device-code request succeeds. On Linux, that request uses
  `https_proxy` with CONNECT and then TLS. Failures stay on the sign-in row.

- **Windows preview paths with backslashes (#640).** A local image or file
  preview resolves an OSC 7 directory such as `/D:\dir` together with a
  backslash-relative path, so `openFileAbsolute` can open it.

- **Agent shell commands freezing the window (#639).** `powershell_exec` /
  `shell_exec` stop when the direct child exits instead of waiting forever on
  a pipe whose write end was inherited by a grandchild.

## Compatibility

- This is a desktop-only release; WispTerm Remote web console versions are
  unchanged. Linux AppImage remains experimental.
- New proxy keys default off. Existing configs keep connecting directly until
  **Use proxy** is turned on.

## Performance baseline

- The Windows x86_64 CPU terminal-stream baseline is attached to the GitHub
  release as `benchmark-windows-v1.40.0.md`, collected with
  `wispterm-bench --case terminal-stream --duration 1000` in ReleaseFast mode.
  It measures parser throughput, not GPU rendering or input latency.

# WispTerm v1.40.0（中文）

> 可以在 LLM 提供商表单里登录 Codex、Kimi 和 xAI 订阅。模型请求可以走系统代理，
> 也可以指定 `host:port`。`/btw` 侧对话可以调用工具。无需手动迁移配置。

## 新增

- **Codex、Kimi、xAI 订阅登录（#641）。** 新建或编辑 LLM 提供商时可以发起
  device-code 登录，拿到验证码后打开浏览器。Codex 必须登录。Kimi 和 xAI
  仍可以使用 API key。令牌保存在 `ai_profiles` 旁边的 `oauth.json`，并会自动
  刷新。ACP 外部代理路径已移除；以前保存的 `acp` 配置会按普通 HTTP 配置加载。

- **为模型请求选择代理（#643）。** 设置 → AI 与集成里有 **使用代理** 和
  **代理**。关闭时仍然直连。打开且地址为空时走系统代理：Windows 用 WinHTTP，
  macOS 用系统网络会话，Linux 用 `https_proxy` / `http_proxy` / `all_proxy`。
  本机开了多个代理时，把 `http-proxy` 设为 `127.0.0.1:6789` 或
  `http://host:port`。开关打开后，流式回复会在整段响应返回后显示。

- **`/btw` 里的工具调用（#638）。** 用 `/btw` 打开的侧对话可以调用和主 Copilot
  回合相同的助手工具。

## 修复

- **订阅登录会打开浏览器（#642）。** 只有 device-code 请求成功后才打开验证页。
  Linux 上这次请求会按 `https_proxy` 先 CONNECT 再走 TLS。失败原因留在登录行上。

- **带反斜杠的 Windows 预览路径（#640）。** 本地图片或文件预览会把 OSC 7
  目录（例如 `/D:\dir`）和反斜杠相对路径拼成系统能打开的路径。

- **代理命令把窗口卡住（#639）。** `powershell_exec` / `shell_exec` 在直接子进程
  退出后结束，不再因为孙进程继承了管道写端而一直等下去。

## 兼容性

- 本次仅发布桌面应用，WispTerm Remote 网页控制台版本不变。Linux AppImage
  仍为实验性构建。
- 新的代理配置默认关闭。现有配置在打开 **使用代理** 之前仍直接连接。

## 性能基线

- GitHub Release 附带 `benchmark-windows-v1.40.0.md`，记录 Windows x86_64 上
  ReleaseFast 构建运行 `wispterm-bench --case terminal-stream --duration 1000`
  的结果。该基线衡量终端解析吞吐量，不代表 GPU 渲染或输入延迟。
